### Step - 3
**Description**
Rewrite the column-lineage collection in `src/databricks/labs/dqx/actions/lineage.py`
so it recurses with the same semantics as the table walk:

- Replace `_column_direction_df` with a recursive-CTE implementation
  parametrised on direction (`_EDGE_COLUMN_UPSTREAM` /
  `_EDGE_COLUMN_DOWNSTREAM`) and seeded from the failed-columns set:
  - Upstream: at depth 1, select rows where
    `target_table_full_name = <anchor>` AND `target_column IN (<failed>)`;
    at deeper hops, join back on `target_table_full_name = e.neighbour_table`
    AND `target_column = e.neighbour_column` (i.e. previous depth's source
    becomes the new target).
  - Downstream: symmetric — depth 1 filters on
    `source_table_full_name = <anchor>` AND
    `source_column IN (<failed>)`; deeper hops chain via
    `source_table_full_name = e.neighbour_table` AND
    `source_column = e.neighbour_column`.
  - Cycle guard: carry `path ARRAY<STRING>` of `concat_ws('.', table, column)`
    identifiers and reject re-entry via `NOT array_contains(e.path, ...)`.
  - Emit per-hop `depth` from 1 upward, bounded by `e.depth < max_depth`.
  - Apply the same `LIMIT {max_nodes}` guardrail at the tail.
- Because Spark cannot correlate a DataFrame join inside the recursive CTE,
  collect the failed-columns names on the driver
  (`failed_columns_df.collect()` — the set is already small and distinct
  by construction), escape each via `_sql_str_literal`, and inline them
  as an SQL `IN (...)` list literal. Short-circuit with an empty
  `_empty_lineage_df` when the set is empty so no query fires.
- Preserve the existing broad-exception logging (`_sanitize`) and empty-df
  fallback semantics.
- Update the `_project_edge_rows` call site so `depth_col` becomes
  `F.col("depth").cast("long")` (the real recursion depth) rather than the
  hard-coded `F.lit(1)`.
- Update the `_column_direction_df` (or renamed helper) docstring to
  describe: (a) recursive traversal semantics, (b) that `search.depth`
  and `search.max_nodes` bound the walk like the table walk, and
  (c) that the failed-columns set is inlined as an IN-literal.
- Refresh the `_collect_column_lineage_df` docstring `Args:` block —
  `search` now bounds depth *and* per-direction row count, not just row
  count.
