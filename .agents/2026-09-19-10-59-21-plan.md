    1. High — extract_failed_columns() reads *every* row of context.output_location

# Plan

### Step - 1
**Description**
In `src/databricks/labs/dqx/actions/lineage.py`, thread `context.run_id` into
the failed-columns extraction so only the current run's failures seed
column-lineage:

- Change `extract_failed_columns(spark, output_location)` to
  `extract_failed_columns(spark, output_location, run_id)`; after each
  `F.explode(F.col(issues_col)).alias("issue")` step, add a
  `.where(F.col("issue.run_id") == F.lit(run_id))` filter *before* exploding
  `issue.columns`. Update the docstring to document the run-id scoping and
  keep the graceful-empty behaviour on missing table / read failure.
- Change `_resolve_failed_columns(*, spark, output_location, safe_name, run_id)`
  to accept and forward `run_id`; the `output_location is None` guard remains
  unchanged.
- In `CollectLineageAction._execute`, pass `context.run_id` when calling
  `_resolve_failed_columns`.
- Keep `extract_failed_columns` in `__all__`; the new required argument is
  a public breaking change of this internal-since-unreleased helper — that is
  acceptable because the action is still `beta` (see the guide's
  FeatureLifecycleStage).
