# Review: PR #1534 — CollectLineageAction and action extras

PR: https://github.com/databrickslabs/dqx/pull/1534  
Related issue: https://github.com/databrickslabs/dqx/issues/1266  
Reviewed branch: `feature/lineage_action`  
Date: 2026-09-19

## Findings

- **High — Column lineage can be attributed to the wrong run.** `extract_failed_columns()` reads every row in `context.output_location` and takes distinct failed column names without filtering the issue structs by `context.run_id` (`src/databricks/labs/dqx/actions/lineage.py:299-345`). In append mode, a failure from an earlier run can seed column-lineage rows stamped with the current run ID (`lineage.py:278-295, 455-459`). A current run with no failure in that column can therefore appear to have one. Filter the source failures to the current run and cover successive runs against the same output table.

- **High — `max_nodes` does not bound recursive traversal work.** The upstream and downstream query applies `LIMIT` only after the recursive CTE and `SELECT DISTINCT` (`src/databricks/labs/dqx/actions/lineage.py:595-617`). A dense graph can generate many paths before the limit applies, so the documented hard cap on nodes visited is not enforced. This can make action execution unexpectedly expensive or fail on large lineage graphs. Bound expansion within the traversal, and test a branching graph that exceeds the configured cap.

- **Medium — The guide promises removed functionality and nonexistent columns.** The documentation says the action collects last-modifier lineage and supports `LineageEntitySearchConfig` / `entities` (`docs/dqx/docs/guide/actions_and_alerts.mdx:510-538`). Its schema table also lists `last_modifier` and several `modifier_*` fields (`actions_and_alerts.mdx:551-570`). The implementation has only upstream, downstream, and columns configuration and no modifier fields (`src/databricks/labs/dqx/actions/lineage.py:69-136, 192-203`). As written, the documented configuration fails validation and the documented queries cannot work. Update the guide to describe the delivered action and schema.

## Verification

- Focused unit tests: `20 passed` (`tests/unit/actions/test_lineage_action.py`, `test_lineage_serializer.py`, and `test_evaluator_extras.py`).
- Workspace integration tests were not run in this review.
- The working tree was unchanged during the read-only review.

## Final verdict

**Request changes before delivery.** Resolve the two high-severity correctness and performance findings and align the documentation with the implementation. The PR is currently marked as a draft.
