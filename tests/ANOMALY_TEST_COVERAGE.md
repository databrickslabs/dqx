# Anomaly test behavior inventory

Maintain this file when an anomaly contract, execution route, dependency boundary or test module changes. It maps observable behavior to tests; it is not a coverage percentage or a list of assertion counts. Test declarations in helper files do not count as collected tests. Confirm new suites with `pytest --collect-only`.

## Execution boundaries

| Layer | What executes | Required dependencies | What a pass does not establish |
| --- | --- | --- | --- |
| Unit | Public pure functions, real local estimators, injected autospec boundaries, temporary local artifacts and nested pytest lifecycle tests | Installed test/anomaly extras; no Spark session, workspace or serving endpoint | Spark execution, UC persistence, worker dependency parity or remote model quality |
| Spark contracts | Real expressions, transforms, joins and materialized rows | Spark and estimator libraries; selected checks can run on local Spark | Databricks classic/serverless compatibility or UC permissions |
| Anomaly integration | Public train/calibrate/score and registry flows | Authenticated workspace, Spark, MLflow and Unity Catalog; SHAP for attribution | Fresh-process packaged deployment unless explicitly tested |
| Live explanation | SQL serving response and degradation smoke | Integration dependencies plus an available configured serving endpoint | Deterministic narrative quality or serving invocation counts |
| Packaged E2E | Exact wheel installed in separate train and score tasks; persisted model reload and actual worker scoring | Workspace Jobs, configured classic or serverless compute, MLflow/UC and built wheel | Other artifacts or compute environments not represented by the recorded provenance |

Shared `anomaly_scorer`/`create_anomaly_apply_fn` helpers default to driver scoring, contributions off and AI explanations off. Tests that use public APIs directly follow those APIs' defaults. A helper default or absent keyword is not evidence for both execution routes.

The central scoring matrix uses distribution single-model, distribution ensemble-of-three and correlation single-model, each with plain and combined group/time contexts. Every case selects driver/worker and contribution off/on explicitly, producing 24 primary scoring paths. It uses numeric and categorical inputs, duplicate rows, null metrics/timestamps, unseen/null groups, stale timestamps and pre-existing score/contribution fields. Three combined-context cases additionally reorder/repartition input and repeat filtered checks. AI is disabled so model-serving availability cannot mask scorer failures.
